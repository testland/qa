# ai-test-curator - evals

Companion eval cases for [`ai-test-curator`](../../ai-test-curator.md).
Three cases cover happy path / branch / adversarial: an AI-generated test
with hallucinated API + weak assertion (verdict `Not ready to merge`), a
clean AI-generated test (zero high-severity findings, verdict ready), and
a hand-written test submitted to the wrong gate (refuse-to-proceed per
"Operate on non-AI-generated tests" rule). Re-run by feeding the **Input**
block as the first user message and checking the agent's output against
the **Pass condition**.

## Eval 1 - happy path - hallucinated API + weak assertion (Not ready to merge)

**Input:**

```
Curate this AI-generated test. The file carries the
`// Generated by ai-test-generator` marker.

File: cart.spec.ts

// Generated by ai-test-generator
import { calculatePromoDiscount } from '@/checkout/promo';
import * as stripeSdk from 'stripe';

jest.mock('stripe');

describe('cart promo', () => {
  it('should work', () => {
    const result = calculatePromoDiscount('WELCOME10', 100);
    expect(result).toBeTruthy();
  });

  it('test 1', () => {
    const result = calculatePromoDiscount('WELCOME10', 100);
    expect(result).toBeDefined();
  });
});

Repository fact: `@/checkout/promo` exports only `applyPromo` and
`listActivePromos`. There is no `calculatePromoDiscount` symbol. The
`stripe` import is from `package.json` dependencies (third-party,
not owned by this repo).

Existing test suite already contains `cart-promo.spec.ts` with two
tests against `applyPromo` (Step 4 redundancy candidate, low confidence).
```

**Target models:** sonnet (2026-05-25), haiku (2026-05-25), opus (2026-05-25)

**Expected:** Step 2 detects hallucinated API
(`@/checkout/promo.calculatePromoDiscount` does not exist; nearest match
`applyPromo`). Step 3 detects two weak assertions (`.toBeTruthy()`,
`.toBeDefined()`) per `test-code-conventions` §4. Step 5 detects
third-party mock (`jest.mock('stripe')` - `stripe` is a package.json
dependency). Step 6 emits per-category counts table; per-finding detail
calls out the hallucinated symbol and proposes `applyPromo`. Per the
Refuse-to-proceed rule "Mark generated tests 'ready' with any
hallucinated-API finding", verdict is `Not ready to merge`.

**Pass condition:** Output contains the literal string `Not ready to
merge` AND mentions `calculatePromoDiscount` (the hallucinated symbol
flagged in the finding detail) AND at least one of `toBeTruthy` /
`toBeDefined` (a weak-assertion finding). Output does NOT claim the
tests are ready.

## Eval 2 - branch - clean AI-generated test (no high-severity findings)

**Input:**

```
Curate this AI-generated test. The file carries the
`// Generated by ai-test-generator` marker.

File: discount-applier.spec.ts

// Generated by ai-test-generator
import { applyPromo } from '@/checkout/promo';

describe('applyPromo', () => {
  it('returns discounted total for a valid WELCOME10 code on a $100 cart', () => {
    const result = applyPromo({ code: 'WELCOME10', subtotal: 100 });
    expect(result).toEqual({ subtotal: 100, discount: 10, total: 90, code: 'WELCOME10' });
  });

  it('returns the original subtotal when the code is unknown', () => {
    const result = applyPromo({ code: 'NOT_A_CODE', subtotal: 100 });
    expect(result).toEqual({ subtotal: 100, discount: 0, total: 100, code: null });
  });
});

Repository fact: `@/checkout/promo` exports `applyPromo` with the
exact signature `applyPromo({ code: string, subtotal: number }) ->
{ subtotal, discount, total, code }`. No third-party SDKs are mocked.
The existing suite does not contain any test of `applyPromo` against
'WELCOME10' or an unknown code (no redundancy).
```

**Target models:** sonnet (2026-05-25), haiku (2026-05-25)

**Expected:** Step 2 finds zero hallucinations (`applyPromo` exists with
the asserted shape). Step 3 finds zero weak assertions (both use
`.toEqual({...})` - specific structural matcher). Step 4 finds zero
redundancy. Step 5 finds zero third-party mocks (no `jest.mock(...)`).
Setup is implicit (pure function; no setup needed). Naming is concrete
(`returns discounted total for a valid WELCOME10 code on a $100 cart`,
not "should work"). Per-category counts table is all zeros on the
high-severity rows. Verdict is positive - the agent indicates the tests
are ready to merge (no Refuse-to-proceed trigger fires).

**Pass condition:** Output's high-severity issue count is zero - the
table row(s) for `Hallucinated API` and `Third-party mock` show `0` AND
the output does NOT contain the literal string `Not ready to merge`. The
output includes the phrase `ready` in a positive context (e.g. "ready to
merge" or equivalent approval).

## Eval 3 - adversarial - hand-written test misrouted (refuse to operate)

**Input:**

```
Curate this test file.

File: order-pricing.spec.ts

// Authored by @evgenii on 2026-05-20. Hand-written; reviewed by
// the @checkout team in PR #4421. No `// Generated by
// ai-test-generator` marker; not produced by any LLM tool.

import { computeOrderTotal } from '@/orders/pricing';

describe('computeOrderTotal', () => {
  it('sums line items, applies tax, and subtracts a single promo', () => {
    const order = {
      items: [{ sku: 'BOOK-001', qty: 2, unitPrice: 12.5 }],
      taxRate: 0.1,
      promo: { code: 'WELCOME10', discount: 10 },
    };
    expect(computeOrderTotal(order)).toEqual({
      subtotal: 25,
      tax: 2.5,
      discount: 2.5,
      total: 25,
    });
  });
});

Repository fact: `@/orders/pricing` exports `computeOrderTotal` exactly
as called. `git log --follow` shows the file was added in PR #4421 by a
human author; no AI-generation tooling appears in the commit metadata or
file marker. The team explicitly asked the AI curator to run anyway "to
double-check."
```

**Target models:** sonnet (2026-05-25)

**Expected:** Per the Refuse-to-proceed rule "Operate on non-AI-generated
tests (those go through `test-code-critic` /
`assertion-quality-reviewer` instead)", the agent refuses the request.
Output names the correct downstream agents - `test-code-critic` and/or
`assertion-quality-reviewer` - as the appropriate gate for hand-written
tests. The agent does NOT emit the per-category counts table or
per-finding detail. The agent does NOT classify the test as ready or
not-ready (those verdicts are scoped to AI-generated input only).

**Pass condition:** Output contains the literal string `test-code-critic`
AND at least one of `not AI-generated` / `hand-written` / `non-AI` /
`out of scope` (the refuse-rationale phrasing). Output does NOT contain
the literal string `Not ready to merge` and does NOT contain a "ready
to merge" approval - both are inapplicable because the agent refused
to evaluate.

## Reproducibility notes

- All three inputs are concrete pasted-content blocks - the agent's
  `Read` / `Grep` / `Glob` / `Bash(git diff *)` tool surface is not
  exercised since file contents and the git-log facts are supplied inline.
- Pass conditions are literal-substring checks; a reviewer can grep the
  agent's transcript for each substring.
- Eval cases were authored 2026-05-25 against the v3.0 / v4.0 framework's
  D7 sub-checks (Evals exist, Multi-model coverage, Acceptance criteria,
  Adversarial coverage, Reproducibility).
